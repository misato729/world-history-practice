# 模擬試験の今回の演習結果

2026年11月1日。ユーザー依頼「模擬試験終了後の結果発表画面」「集計・終了操作まで実装する」に対応。

## 動作

最初の回答、スキップ又は終了操作時に、その時点の対象問題・内容版・形式・配点・表示順を1回分の演習として固定する。画面移動は同じ回を引き継ぐ。「演習を終了して結果を見る」又は最終問の「結果を見る」で終了し、未回答があれば件数と「未回答の問題へ戻る」「演習を続ける」「未回答のまま終了する」を表示する。

結果は模試ごとに、対象問数・回答数・未回答数、選択/語句記述の点数と正答数、論述の参考点・未採点/保留、各問題と解説への振り返り、新しい回としての解き直しを表示する。4大問30問・選択20/語句8/論述2の全対象が一致する場合だけ全体結果とし、部分演習を100点へ換算せず、複数模試を合算しない。配点の正本は `config/exam.json` の3/3/8点。論述に未回答・保留・条件不成立があれば総合点は未確定で、未採点を0点と表示しない。公式得点・合否判定ではなく学習用参考配点と明示する。

会員の回はDBへ保存し、本人がURLから再表示できる。過去の通常履歴や他の回を集めず、この回で最初に受理した回答だけを使う。同じキー/内容の再送は同じ結果、別回答は競合とする。履歴と回の回答は同じトランザクションで確定する。終了後の新しい回答は拒否し、解き直しは別の回を作る。

未ログインはタブ内メモリのみの参考結果で、再読込・タブ終了で失われる。APIから受け取る署名付き対象情報で現在の版を確認するが、ゲストの答案・回はDBへ保存しない。通信失敗だけで結果を破棄せず、再確認できる。認証状態が変われば回と回答を引き継がない。通信エラー時に内部APIのパスや例外文を表示しない。

内容・正答・参照本文、公開状態や対象集合の変更は、Writerと同じトランザクション内のトリガーで関係する回を失効させる。分類・表示順だけの変更や対象外の部分演習は保持する。取得・回答・終了でも所有者、利用資格、内容版、配点、論述プロフィール/エンジンを確認する。回答前には正答・モデル・解説を返さない。

## 導入と作業範囲

新しい番号付きSQL `008_practice_attempts.sql` を追加した。**008を適用したのは独立したローカル検証DBだけで、通常の接続先・公開環境へは適用していない。** 利用環境へ反映する際は、その環境の正規の `npm run db:migrate` で008を適用してから、このAPIと画面を使う。既存001〜007は変更していない。DB操作は検証用に限り、通常/公開DBの問題・利用者・履歴・お気に入り、配信設定を変更していない。コミット・push・デプロイは実施していない。

実際のNuxt/APIと、独立した `_test` DBの合成30問/4大問を使った。検証用会員と署名キー・Cookie名も通常環境から分離した。原資料・実問題・通常の利用者・本番の配信先を検証に持ち込んでいない。開始時からあった別作業の差分は保持し、この実装の変更に数えない。
