## 採点する範囲

採点時にAI・外部採点API・学習済みモデルを使わず、サーバー内の有限の文字列・語順・近接条件で判定する。12プロフィール・53要素は作成済み論述の字数・指定語・要素・参考配点を継承し、各問8点とする。模範解答は変更していない。

| 要素の状態 | 点数 | 意味 |
| --- | --- | --- |
| 確認できた | その要素の参考配点 | 登録した表現と関係条件に一致 |
| 誤りの条件に一致 | 0点 | 登録した誤りの表現に一致し、否定等の解釈が未解決でない |
| 判定保留 | 未確定 | 未登録の表現、欠落、否定のかかり先、正誤併記、仮定・引用等を機械で区別できない |

全要素に判定がつき、字数・指定語を満たすと「ルール採点の参考点：○ / 8点」を表示する。保留があれば「確認できた得点：○ / 8点」「残り○点分は判定保留」とし、合計点はnullのまま。0点と保留を区別し、どちらも小問全体の不正解という真偽値に変換しない。字数・指定語の条件違反も、参考点未確定として理由を示す。

登録した表現に合ったことは、自由な文章全体の意味・追加の史実まで理解して正しいと保証したことではない。230例は開発用に作った合成答案であり、学習者の実答案での一致率・誤採点率は未測定。参考点を歴検公式点・合否判定へ置き換えない。

## 問題の登録と版の管理

管理画面で新しい小問の回答形式を「論述（要素別ルール採点）」にし、該当するプロフィールと版、模範解答を指定する。問題文・本文参照・解説・出典は従来どおりDBへ登録する。今回のカタログは採点ロジックの定義であり、問題DBへの自動投入元ではない。

公開時には、既知のプロフィールと版であること、模範解答が全要素8点となること、字数・指定語を満たすことを検査する。採点規則を選ばない空の下書きは保存できる。公開済み回答形式の固定を守り、既存の選択・語句問題を同じIDのまま論述へ変更しない。

問題の `essay_config` にプロフィールID・版・模範解答とサーバー計算のダイジェストを保存する。ダイジェストはプロフィール全内容とエンジン版から計算し、クライアントの値は信頼しない。プロフィールの内容、又はエンジン版が変わって保存値と一致しない場合、取得・回答・履歴表示を409で止める。管理者の再保存で新しいダイジェストが内容変更として検出され、共通Writerの同一トランザクションで内容版増加と影響履歴の削除を行う。お気に入り・ID・対象外履歴は保持する。同一内容の再保存は履歴を削除しない。

公開後の規則変更は新しい版を追加し、参照中の旧版を残す。採点ロジックの変更時には `ESSAY_SCORING_ENGINE_VERSION` を必ず上げる。ダイジェストはエンジンのソース本文そのものの変更を自動検出するものではない。

## API・保存・表示

一般の問題取得では `answer_type: essay` と `essay_constraints`（最大字数・指定語）だけを追加する。模範解答・要素・採点パターン・プロフィールIDは回答前に返さない。管理者限定の `GET /api/v1/admin/essay_profiles` で選択用のID・版・題名・条件・要素を取得する。

通常の回答APIへ `answer_type: essay`、`submitted_text`、問題版、送信キーを送る。サーバーが計算した `essay_result` と `model_answer` を回答後に返す。資格・公開状態・版・本人所有・同一キー再送の検査は既存機能と揃える。画面から送った点数・正誤は採用しない。会員の履歴は `is_correct: null` と採点結果JSONを保存し、再読込・履歴からの復元でも保存した結果を表示する。ゲストはDBへ保存せず、再読込すると表示結果が消える。

新しい番号付きSQLは007。既存の問題・選択肢・利用者・履歴を作り直さず、回答形式の制約を拡張し、論述の設定と結果の項目を追加した。旧選択・語句の正誤は引き続き必須で、論述だけnullを許可する。v2アーカイブは論述設定を往復でき、非論述の空設定は出力から省略して従来の形式とハッシュを保つ。

今回の実装は小問ごとの採点。1セットの試行管理、84点の自動部分と16点の論述参考点を集める結果画面、採点保留を自己採点で確定する機能は未実装。[模試終了時の初期仕様](mock-score-display-spec-20261027.md)の論述未採点段階を、本書の機能が置き換える。保留が残るセットの総合点を確定させない方針は維持する。

## 2026年10月30日の改訂

ユーザー合意により、参考配点を原則4要素×2点とし、設問の要求が3つの説明に自然にまとまる場合は3・3・2点を用いる。合計は各問8点。要素は20字前後を設計の目安にするが、要素別の字数や一文一要素を入力条件にしない。1つの文で複数要素を満たせる。

各要素に複数の許容表現を用意し、同義語・関係を示す言い換えを有限のOR条件で登録する。複合要素は単語の一部だけで加点せず、必要な事実と関係がそろった場合にその配点を加える。未知表現は引き続き保留とする。新ルールは主体との密着した句や関係述語を用い、列挙、主体の入れ替え、「運ばず」「残らず」等の否定、未実施の表現も検査する。

| 対象 | 配点と版 |
| --- | --- |
| 囲い込み、産業革命 | 従来の細分要素を4要素×2点にまとめた第2版を追加 |
| 産業革命期の公衆衛生 | 4要素×2点を維持し、住宅・生活環境の許容表現を追加した第2版 |
| 模試6：アッシリア・インカの駅伝制 | 国別の仕組み各3点、遠隔地連絡と広域支配の関係2点 |

| 模試7：輸入代替工業化と従属理論 | 国内生産への代替、工業化の目的、従属的分業、発展阻害の説明を各2点 |

他の公開7問は既存の4要素×2点・許容ルールを保持する。カタログには旧版を残し、全19プロフィール版を明示版で選択できる。版を省略して取得する場合のみ最新を返す。現行7セットの論述14問は計54要素となる。

結果画面と履歴には「3要素中2要素を確認・参考5 / 8点」のように確認要素数と参考点を別々に示す。残り3点分が保留ならその旨も表示する。字数・指定語違反では参考点未確定とする。保存値 `score` は保留時にnullのままとし、表示する加点済み参考点を確定総合点に置き換えない。論述履歴の正誤はnullを維持する。

判定エンジン・結果JSON・DBスキーマは変更していない。旧版の内容とダイジェストを保持し、対象7問の設定・新4問の解説を共通Writerで同一トランザクション内に更新する。問題・選択肢ID、お気に入り、対象外データ、公開状態を保持する。対象設定変更は内容版を増やし、影響する回答履歴を無効化する。同じ内容の再保存では版を増やさず履歴も削除しない。模試6・7は下書きを維持する。

有限ルールなので、正しい未知表現や、一文内で第1次・第2次の主語を切り替える一部の比較は保留になり得る。合成答案の検査結果を実答案の精度保証とはしない。今回の検証・独立レビュー・画像・変更ファイルはローカル専用の [検証記録](../local-only/essay-weighted-scoring-20261030/verification.md)に記録する。

今回の検査は関連unit348件、隔離DBのAPI統合3件、全14モデルの8点、採点定義・表示関数等5ファイルのstrict型検査。表示は実部品/CSS・履歴バッジを合成応答で隔離表示し、PC1440px・スマートフォン390/320pxで操作・折返し・横はみ出しを確認した。通常Nuxt画面全体の起動と全体型検査は長時間処理を中断しており、完了済みとは扱わない。検証用アプリ・DBは終了・削除済み。
