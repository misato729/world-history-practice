# リード文と小問・下線の順序

2026年10月28日の追加方針。以前の本文改稿の記録とは分け、今回の並べ替えを記録する。

## 採用する方針

1. 同じリード文に対応する小問をまとめる。【A】の小問群を終えてから【B】へ、次に【C】へ進み、同じ大問内で前の本文へ戻らない。
2. 本文の下線を出現順に(a)・(b)・(c)…と付け、対応する設問もそのアルファベット順に配置する。同じ下線を使う小問は連続させ、互いの順序は保持する。並びを取り繕うために下線のラベルや参照先を付け替えない。

本文全体を参照する小問は、同じ本文の小問群内で内容に応じて位置を決める。現データで唯一の例である模試2大問3・内部番号21は、既存の全体参照を保ち、【A】の下線付き小問の後へ置く。任意の下線へ結び直したり、全体参照には常に末尾という無条件の規則に広げたりしない。

[AGENTS.md](../AGENTS.md) と [作問要件のLEAD-03・REF-02](mock-exam-authoring-requirements-20261028.md) にも統合する。これはユーザーが指定した今回の教材の方針であり、すべての年度の公式過去問に例外なく適用されるという調査結果ではない。

## 全20大問の監査

通常ローカルDBの5セット・20大問・150問・34本文・103下線を対象とする。各小問の参照は149件の下線参照と1件の本文全体参照で、すべて所属と参照先が一致した。

- 本文が途中で戻る箇所は、指定の模試1大問2・模試2大問2・模試3大問2/3・模試4大問3に加え、模試5大問2にも確認した。合計6大問。
- 各本文内に投影すると、下線の順序が戻る箇所は15大問。上記と合わせて16大問を並べ替え、81小問の表示位置が変わる。
- 模試1大問1/4・模試3大問4・模試4大問2の4大問は、そのままで両方の条件を満たす。元の模試1大問1の8問は配列も内容も保持する。
- 模試4は7・8・7・8問。他のセットの8・7・8・7問を全セットの固定配分として使わない。

例として模試1大問2は、次の配列へ変更する。

| 順序 | 参照配列 |
| --- | --- |
| 変更前 | A(a)・A(b)・A(c)・B(e)・A(a)・B(d)・B(d) |
| 変更後 | A(a)・A(a)・A(b)・A(c)・B(d)・B(d)・B(e) |

全20大問の変更前・変更後の参照列と内部番号の対応は、私的な `local-only/mock-question-order-20261028/audit-review.md`、同JSON、`plan.json` に保存する。元の原稿・以前の承認時の期待値は書き換えない。

## 表示順と永続的な番号

問題ID、既存URLで使う `question_number`、問題本文・全選択肢・解答・解説・本文・下線・参照先・分類・論述のモデル/字数/採点ルールは保持する。大問内の表示用 `group_question_number` だけを新しい順へ付け直す。論述も参照する下線の位置に従って移動し、設問や要求量自体を改作しない。

通常の並べ替えと同じ共通Writerの `saveQuestionGroup(question_ids)` をトランザクション内で使用する。配置だけの変更のため `content_version` を増やさず、回答履歴やお気に入りを削除しない。実際に位置が変わるのは81問だが、共通Writerは対象16大問の全120問の更新日時・編集競合用の版を更新する。残る4大問30問は保存処理自体を呼ばない。同じ配置の再実行でも保存処理を呼ばない。

一般画面はAPIからの表示順を既に維持する。順次取得APIの `after_question_number` は、内部番号の大小だけでは表示順に従えないため、同じ試験の公開小問の大問番号・大問内番号・内部番号を使って次を判定する。章節・文化史条件とアクセス条件を維持し、非公開や別試験の小問をカーソルとして扱わない。先頭指定0、実在しない/非公開のカーソルに対する従来の数値境界は互換性を保つ。

以前の登録・改稿用の一回限りのスクリプトや原稿は、以前の大問内番号を前提とする。将来の内容更新で、原稿の旧小問番号を現在の大問内番号と同一視して問題を上書きしない。実問題の正本であるDBの問題ID・内部番号・参照先と照合する。
