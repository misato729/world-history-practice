# 模擬試験終了時の得点表示仕様案

**2026-10-28の実装状況：** [論述要素別ルール採点](essay-rule-scoring-20261028.md)で、通常演習の論述入力・非AI参考採点・履歴・管理を実装した。以下の「論述は紙で解き未採点」は初期段階の設計記録であり、現行の小問機能は後続仕様を適用する。1セットの試行保存・合計結果画面・自己採点反映は引き続き未実装。保留がある総合点を確定しない。

作成・コード確認日: 2026年10月27日（UTC）。ユーザーの「模擬試験を1セット解き終えたら点数を表示する仕様」「論述の採点は後で検討し、まず問題と解答を作る」という依頼に対する設計。当初は仕様書だけを作成した。現在の実装状況は冒頭の追記と後続仕様を参照する。

## 1. 今回決めること

1セットの演習を終えると、その回に取り組んだ問題だけを集計する。選択問題・語句記述は自動採点する。論述は問題・指定字数・模範解答・必要要素と因果関係を用意し、初期段階では採点しない。全30問を終えても、論述16点分が未採点なら「自動採点 ○点 / 84点」「論述 16点分 未採点」「総合点 未確定」を表示する。

これは1問ずつ答えと解説を確認する学習用の得点である。制限時間、一括提出、解答を最後まで隠す試験モード、公式の合否判定は今回の仕様に含めない。論述の入力・答案保存・自己採点の反映も後続機能とし、今回の作問完成をそれらの実装完了とは扱わない。

配点は[表示整理で記録したユーザーの参考案](mock-exam-hierarchy-20261027.md#配点の参考案)を使う。

| 形式 | 問数 | 1問の配点 | 満点 | 初期の扱い |
| --- | ---: | ---: | ---: | --- |
| 選択 | 20 | 3点 | 60点 | 自動採点 |
| 語句記述 | 8 | 3点 | 24点 | 自動採点 |
| 論述 | 2 | 8点 | 16点 | 問題と模範解答を確認。未採点 |
| 全体 | 30 | — | 100点 | 自動採点部分は84点満点 |

この配点は世界史ラボの学習用参考配点と明示する。歴史能力検定の公式配点や合格見込みには置き換えない。公式の配点が非公開であることの確認URL・更新日・確認日は、上記の記録を参照する。

## 2. 全体演習と部分演習

得点を出す範囲を、開始時点で固定する。「模擬試験n」を表示しているだけで全30問を解いたとは判定しない。

| 開始した範囲 | 結果の名称と分母 |
| --- | --- |
| 完成した1セットの4大問・全30問 | 「模擬試験nの演習結果」。選択20・語句8・論述2と配点を検査し、自動84点・論述16点 |
| 大問1つ、分野での絞り込み、旧URLの小問指定 | 「選択した問題の演習結果」。対象問題の配点だけを合計 |
| 現在収録されている1大問8問 | 「大問演習の結果」。四択6・語句2なら24点満点。100点へ換算しない |
| 複数の模擬試験を選択 | 現行の連続演習として扱う。1セットの得点には合算しない。得点付きで取り組むときは模擬試験ごとに開始する |
| 条件一致0問 | 開始できない。0点や0/0の結果を作らない |

順次・ランダムの違いは表示順だけで、対象集合・配点・分母を変えない。部分演習に論述が含まれる場合も、自動採点の分母と論述の未採点配点を分ける。例えば自動採点4問・論述1問なら自動12点満点、論述8点分未採点であり、100点へ比例換算しない。論述だけを選んだ場合は「自動採点対象なし」と論述の未採点配点を表示し、自動採点0/0点を作らない。

全体演習は、公開検査済みの1教材について、実在する公開大問4件・小問30件と形式内訳がすべて一致したときだけ開始できる。現在の `config/exam.json` は4大問30問の構成を持つが、20/8/2の内訳と配点設定は未実装である。現行の8問や検証用の22選択/8短答を、この標準配点の完成模試として扱わない。

## 3. 「今回の演習」を識別する

以下の「試行」は、ユーザーが「このセットを始める」を選んでから結果を確定するまでの1回を意味する。ログインの有効期限を管理する認証セッションや、従来の小問回答履歴とは別の識別子を持つ。時間制限のある受験セッションを実装済みとするものでもない。

開始時に、対象教材、全体/部分の区分、問題ID・内容バージョン・回答形式・配点、表示順、配点設定の版を確定する。表示順は保存するが、分類や表示順だけの編集で得点を失効させない。正答・許容表記・模範解答は開始時の一般APIへ渡さない。

集計するのは、その試行に紐づいて受理された回答だけとする。過去に同じ問題を正解した履歴、別タブでの通常演習、履歴から開いた正答、他の模擬試験の回答を取り込まない。「各小問の最新回答を履歴全体から集める」方法は使わない。

### 回答・再回答・未回答

- 選択や入力は送信前なら変更できる。送信が成功し、答えと解説が表示された後は、その試行の点数を変更しない。最初の確定回答が誤答なら0点のまま。解き直しは新しい試行を作り、前の結果と混ぜない。
- 通信失敗中の回答は未確定。成功が確認できるまで回答数も得点も増やさない。画面で選択しただけ、入力しただけでは回答済みにしない。
- 答えずに進む操作は「未回答で次へ」とする。後で戻って回答できる。結果確定時に残った自動採点問題の未回答は0点とし、誤答件数とは別に「未回答 n問」を表示する。未回答の配点を分母から外して得点率を上げない。
- 末尾の小問へ直接移動しただけでは終了しない。全対象の回答状態を確認し、未処理があれば戻れるようにする。途中で終える場合は「未回答の問題がn問あります」を表示し、「演習を続ける」「未回答のまま終了する」を選ぶ。
- 終了確定後の自動採点結果は読取専用とする。同じ結果を再表示しても、開始・終了・回答の送信を増やさない。

### 初期の論述の扱い

論述は紙や利用者の手元のメモ等で解き、「模範解答を確認する」で模範解答・指定字数・必要要素と因果関係を開く。初期段階では、Webで論述答案を入力・送信せず、正誤判定も作らない。

論述ごとに「模範解答確認済み」又は「未確認のまま終了」を記録できるようにする。どちらも得点は未採点であり、確認したことを正解・満点・論述回答済みに置き換えない。進捗では「自動採点対象の回答数」と「論述の確認数」を分ける。「30問回答済み」と表示しない。

### 完了条件

標準セットの通常終了は、自動採点28問について回答又は未回答の扱いが確定し、論述2問について模範解答の確認又は未確認の扱いが確定してから、「結果を見る」を選んだときとする。最終問の回答直後の主操作も「結果を見る」にする。全問回答を強制せず、未回答を含めて終了したことを結果に残す。

「全30問の演習終了」と「全30問に答案を提出」と「100点分の採点完了」は別の状態である。初期段階の通常終了でも、100点分の採点完了にはならない。

## 4. 採点と表示の計算

選択は既存の正答1件との一致で3点、誤答・終了時の未回答は0点。語句記述は、既存の `accepted_answers` とNFKC正規化・前後空白除去後の完全一致で3点、それ以外と終了時の未回答は0点。表記揺れは作問時に許容表記として確認し、編集距離・部分一致・似た文字という理由で自動的に部分点を付けない。

自動採点得点は「今回正解した選択数×3 + 今回正解した語句記述数×3」。標準セットの分母は常に84点とする。論述得点は初期段階では `null` 相当の未採点で、0点ではない。総合点も未確定とし、自動得点を100点満点の得点として表示しない。

### 全30問を終えた画面例

以下は選択17問正解、語句記述6問正解、未回答0問、論述2問の模範解答を確認した場合の例。

> **模擬試験1の演習結果**\
> 全30問の演習を終了しました。\
> **自動採点 69点 / 84点**\
> 選択：17 / 20問正解（51 / 60点）\
> 語句記述：6 / 8問正解（18 / 24点）\
> 自動採点対象：28問回答・未回答0問\
> 論述：2問の模範解答を確認済み。16点分は未採点です。\
> **総合点は未確定です。**\
> 世界史ラボの学習用参考配点です。\
> ［問題と解説を振り返る］ ［新しい回として解き直す］

正答率を出す場合は、点数の補助として「自動採点対象の正答率 23/28問（82.1%）」と明示する。23/30問や、69/100点を正答率として表示しない。自動採点84点満点を達成しても、論述未採点の間は「満点」「100点」「合格」を表示しない。

問題一覧は大問順に、選択・語句の「正解」「不正解」「未回答」、論述の「未採点」と模範解答確認状況を表示する。色だけで状態を区別しない。スマートフォンでは得点・未採点・総合未確定を先に置き、内訳と振り返りを縦に並べる。試行ID、DB名、内部の採点状態名は利用者向けに表示しない。

## 5. 保存・認証・ゲスト

| 利用状態 | 方針 |
| --- | --- |
| ログイン済み | APIが対象・所有者・利用資格を検査し、回答と結果をDBへ保存。再読込・同じ会員での再ログイン後に自分の未完了試行を再開し、終了結果を再表示できる |
| 未ログイン | 現行の「回答をDBへ保存しない」を維持。APIが返した今回の正誤だけを、そのタブのメモリで集計し「このタブでの参考結果」と表示。再読込・タブ終了で失われ、会員の保存結果・履歴へ取り込まない |
| 途中でログイン/ログアウト・会員切替 | 画面の集計を別の本人へ引き継がない。ゲスト結果の自動移行は行わず、保存する演習は会員として新しく始める。ログアウト時は会員の回答・結果表示を消す |
| 認証期限切れ・利用資格変更 | APIの現行方針に従って操作を止める。エラーを誤答・0点・演習完了へ置き換えない。再認証・資格確認後に本人の有効な試行だけを再開する |

ゲストの集計は会員結果のようなサーバー検証済みの保存得点ではない。画面上の値を会員の点数としてAPIへ送って採用しない。ゲストにも開始時に「結果はこのタブでのみ確認できます。再読込すると消えます」と案内する。ゲストの再読込時は空の試行を勝手に継続せず、開始画面へ戻す。

会員の結果APIは利用者本人の試行だけを返す。URLに他人の試行IDを指定しても答案・点数・存在情報を取得できないよう、既存の認証・利用資格検査に揃える。問題と模範解答の取得にも公開状態・資格の検査を適用し、論述用の表示追加で答えの事前秘匿を崩さない。答案・正答・点数を運用ログへ記録しない。

## 6. 重複送信・同時操作・内容更新

### 二重送信と別タブ

会員は試行と小問の組に確定回答を最大1件だけ持つ。同じ送信キー・同じ内容の再送は同じ確定結果を返し、履歴・得点・回答数を増やさない。同じキーを異なる内容で使った場合は競合とする。別キーで同じ小問へ再回答しても点数を書き換えず、確定済みと案内する。

回答の受理・試行内の回答確定・既存回答履歴への記録は同じトランザクションで行う。結果確定も試行をロックして一度だけ行い、並行する最後の回答と終了操作の前後関係を決める。終了後に届いた新しい回答は受理しない。終了前に受理済みの回答の再送は、終了後でも同じ結果を返せるようにする。

同じ試行を複数タブで開いた会員には、サーバー上の確定状態を再取得して示す。別タブで同じ問題に異なる答えを送っても、最初に受理された1件だけを使う。ゲストはタブごとに別の一時集計であり、他のタブと合算しない。

### 問題の版が変わった場合

現行Writerは内容更新時に影響する回答履歴を削除し、小問の `content_version` を増加する。過去本文を保存する版テーブルはない。この方針を、点数追加だけを理由に変更しない。

開始後に対象小問の内容・正答・許容表記・採点条件・解説・出典・本文参照が変わった場合、参照する共通本文が変わった場合、対象の公開状態・所属・集合又は配点設定が変わった場合は、その試行を失効させる。古い回答と新しい正答を混ぜて再採点しない。会員の処理では共通Writerの更新と同じトランザクションで関係試行を失効させ、影響小問の回答を現行の履歴削除方針と揃えて除去する。対象外小問の履歴・お気に入り・利用者は削除しない。

失効した結果は「問題が更新されたため、この回の点数は表示できません。新しい回として始めてください」とし、以前の数字を現在も有効な結果として表示しない。進行中・終了済みのどちらも対象とする。過去の不変な得点を保存したい場合は、問題・共通本文・正答・配点の版保存と履歴保持の方針を別途設計する。

分類・表示順だけの変更、同じ内容の再保存では失効させない。開始時の表示順を維持すればよい。競合・更新・非公開を未回答0点で埋めて終了させない。ゲストも取得/回答/結果表示前に対象版の変更を確認し、変更が分かった時点で参考結果を破棄する。通信できず版を確認できないときは、確認待ちとする。

## 7. AI APIを使わない論述採点の候補

推奨は、問題ごとの必要要素チェックに、因果関係・年代順・設問条件の人手確認を組み合わせた自己採点である。模範解答と一字一句同じかではなく、問われた関係を自分の答案で説明できているかを確認する。外部APIの利用料は発生しないが、作問側の基準作成と利用者の判断は必要になる。

採点基準・具体的な答案例を揃え、別担当が基準の内容と適用を確認する考え方は、ETSの一次資料でも扱われる（2021年版、PDF通し26〜29頁/印刷25〜28頁、確認日2026-10-27）。この資料を踏まえた世界史ラボの設計提案であり、歴検公式の採点方式の説明ではない。[ETS: Best Practices for Constructed-Response Scoring](https://www.ets.org/pdfs/about/cr_best_practices.pdf)

| 方法 | 使いどころと制約 | 採用案 |
| --- | --- | --- |
| 必要要素・関係を示した自己採点 | 費用を抑え、足りない知識を具体的に確認できる。言い換えや因果の正しさは本人の判断が残る | 最初に検討する。採点基準と満点/部分点/誤答例を用意 |
| 教員・管理者等による人手採点 | 曖昧な答案や論理の誤りを個別に確認できる。担当者の時間と採点のすり合わせが必要 | 必要になれば任意の添削として検討。今回実装しない |
| キーワードの一致・ルール判定 | 文字数、指定語、明示された表記の有無を示せる。否定、因果逆転、語の羅列、同義表現を十分判別できない | 「見つかった語/確認が必要な項目」の補助表示に限定。論述得点を確定しない |
| 端末内・自前サーバーのモデル | API課金以外の方式だが、環境準備・実行負荷・保守は必要。無料/正確とは一律に言えない | 今回は導入しない。将来も人手による基準答案との比較・誤採点の検証なしに自動得点を信頼しない |

### 8点の抽象的な基準例

以下は計算を確かめるための仮例で、実際の歴史事実や論述問題の採点基準ではない。実問題では確認済みの史実に合わせて観点・別表現・誤りの扱いを個別に決める。

| 観点 | 点数 | 人が確認する内容 |
| --- | ---: | --- |
| 必要要素A | 2 | 語の出現だけでなく、主体と内容が条件に合う |
| 必要要素D | 2 | Aとは別の必要内容を説明している |
| 因果関係 | 2 | A→B→Dのつながりを正しい向きで説明している |
| 年代・前後関係 | 1 | G→Hの順序と他の記述に矛盾がない |
| 設問条件 | 1 | この仮例では60〜100字の指定を満たす |
| 合計 | 8 | 各観点は満点か0点。実問題の部分点は別に明文化する |

抽象答案例: 「要因Aが状況Bを生み、その影響を受けた主体Cが対応Dを進めた。これにより変化Eが起こり、結果Fへつながった。出来事はG、Hの順に置く。」

この例は句読点・英字を各1字として67字であり、指定範囲内である。文字数が条件内でも、因果や年代の正しさを機械で確認したことにはならない。二重減点を避け、同じ欠落を複数観点へ重ねる場合の条件も事前に決める。字数不足だけで答案全体を0点にする等の追加ルールは、この仮例にはない。

### 自己採点を後で反映する場合

論述1問ごとに基準の版・観点の判定・0〜8点の整数得点・自己採点日時を保存し、「未採点」と「自己採点0点」を区別する。初期の模範解答確認状態から点数を推測しない。白紙でも、自己採点時に利用者が0点を明示確認して初めて0点として扱う。

先の自動69点の例で、論述が8点と5点なら「自己採点を含む合計 82点 / 100点」「自動採点69点＋論述自己採点13点」と表示する。片方だけ8点で他方が未採点なら合計は未確定のままにし、「論述自己採点8点、残り8点分未採点」とする。参考配点・自己採点の表示を消さず、公式の確定得点や合否に変えない。

自己採点の変更は自動採点の回答を上書きせず、自己採点の更新版を残して合計だけ再計算する。基準の版が変わったら前の自己採点を新基準へ自動移行せず再確認を求める。サーバーでも範囲・整数・観点合計を検査し、画面から送られた合計点をそのまま採用しない。

## 8. 現行実装との差分と実装時の順序

| 現在確認できたもの | 追加が必要なもの |
| --- | --- |
| `single_choice` / `short_text` の小問取得と回答 | 論述問題と模範解答を表示する回答形式・検証・管理入力。初期は採点対象外 |
| 小問ごとの正誤、会員の回答履歴、内容バージョン | 1回の試行、対象集合・配点版、試行内の回答/未回答、論述確認状態、開始/終了/失効 |
| 会員の同じ送信キーの重複防止 | 試行内の小問一意性、最初の回答の固定、同時終了/回答の整合 |
| 画面の演習順序と末尾の完了表示 | 対象全体の状態確認、結果API・画面、再開/再表示、新しい試行の開始 |
| 内容変更時に関係履歴を削除する共通Writer | 関係試行の失効を同じ更新トランザクションへ統合 |
| ゲスト回答はDB保存しない | タブ内限定の参考集計と破棄・版確認の処理 |

将来のDB拡張案は、試行を表す `practice_attempts`、対象小問と配点・版・確定状態を表す `practice_attempt_items`、将来の自己採点の版履歴を表す表等を、現行の `pg` と新しい番号付きSQLマイグレーションで追加するものとする。名称・列・APIのパスは実装着手時に確定する。既存の問題/選択肢ID・履歴/お気に入りとの関係を保持し、適用済みSQLを書き換えない。試行内の回答を既存履歴IDだけに依存させず、履歴削除時も失効判定が残る関係を設計する。

現在の `answer_histories.is_correct` は必須の真偽値で、未採点を表せない。初期の論述の確認状態は試行内の項目へ持たせ、この履歴へ不正解として挿入しない。将来の論述答案と採点状態も、未採点・0点を別々に表せる構造へ追加する。既存の `short_text` に論述を詰め込み、完全一致で採点する実装にはしない。

配点・形式内訳の正本は将来 `config/exam.json` に設定として追加し、公開検査と試行開始の両方で検査する。現時点で設定・制約・APIを変更したものではない。既存の四択/語句問題を、同じIDのまま論述形式へ変えない。論述は新しい小問として登録し、公開後の回答形式固定を守る。

実装は、(1)配点/論述表示の構造と公開検査、(2)試行・回答・失効の処理、(3)会員結果とゲスト参考集計、(4)結果画面と操作確認、の順に小さく分ける。自己採点の保存・採点補助・人手添削は、方式の検討と別の実装依頼後に進める。今回の仕様依頼をDB投入・コミット・push・デプロイの許可へ広げない。

## 9. 実装時の受入条件

- 全体30問と部分演習を区別し、20×3＋8×3＋2×8＝100、自動部分84、現在の8問24を検査できる。条件0件・複数模擬試験・ランダムでも分母を誤らない。
- 同じ利用者の過去履歴、別試行、他人、ゲスト、履歴復元、別タブの通常演習を混ぜない。再読込と結果再表示で点数が変わらず、新しい回は0回答から始まる。
- 初回正解/誤答、未回答での終了、通信再送、二重クリック、別キーでの再回答、同時送信/終了を確認し、1小問を二重計上しない。
- 論述の確認有無と採点状態を区別する。全30問終了でも自動○/84・論述16未採点・総合未確定となり、論述未採点を0にしない。将来の自己採点1件未了・全件完了・0点・修正でも合計と表示が一致する。
- 内容/共通本文/公開状態/対象集合/配点の更新で該当試行を失効させる。分類・並べ替え・同一再保存では不要な失効や履歴削除を起こさない。
- 認証・本人所有・資格と正答秘匿をAPIで検査し、ゲストに保存結果があるように表示しない。ゲストの再読込と会員切替で回答を引き継がない。
- 末尾 `_test` の隔離DBでトランザクションと再実行を検証し、PCとスマートフォンの実操作で終了/未回答確認/結果/振り返り/再開を確認する。今回の文書点検を実装・DB・画面の検証済みとしない。
