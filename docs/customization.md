# 世界史ラボの設定・問題更新手順

現在の通常ローカルDBは自作1大問8小問（四択6・語句記述2）です。教材・大問・共通本文・小問と語句記述を管理できます。機能の追加だけでは新しい問題は登録・公開されません。課金・販売は無効です。価格・決済手段・運営者情報・公開先は未確定で、以下の課金手順は将来の設定方法です。

## 設定と問題データの役割

| ファイル・場所 | 役割 |
| --- | --- |
| `config/exam.json` | 試験別設定の正本。フロントとAPIが同じファイルを読む |
| `content/questions.json` | 合成テスト・検証用のv1サンプル。空DBへの明示取込用で、実問題の更新元にはしない |
| `frontend/public/images/` | ロゴなどの公開素材 |
| 管理画面・DB | 実問題・教材構成・公開状態の正本 |
| `.env` | 開発用ポート、DB接続、認証・決済等の環境ごとの設定 |

`config/exam.json`は公開情報だけを保存します。秘密鍵・DBパスワード・利用者情報は記載しません。

## ブランドと説明を変える

`site`で以下を指定します。

| キー | 内容 |
| --- | --- |
| `id` | サービスごとに一意な識別子。英小文字で始まる40文字以内の英小文字・数字・ハイフン。このサービス：`world-history-practice` |
| `name` | サービス名 |
| `short_name` | 短いサービス名 |
| `exam_name` | 対象資格・試験の名称 |
| `description` | サービスの説明 |
| `tagline` | トップページの短い案内 |
| `logo_path` | `frontend/public`から配信するロゴのパス。例：`/images/logo.svg` |
| `primary_color` | 基本色。`#2563eb`のような6桁のカラーコード |
| `contact_email` | 問い合わせ先。空欄のまま一般公開しない |
| `overview` | 試験概要ページの本文。`title`と`body`の組を並べる |

`site.id`はログインCookieの名前にも使います。本番環境でもlocalhostの別ポートでも、別サービスには異なる値を設定してください。運用途中で変更すると、以前のCookieを使ったログイン状態は引き継がれません。

ロゴ素材自体の色を変える場合は、SVG等のファイルも編集してください。利用規約・プライバシーポリシー・特定商取引に関する表示は共通の草案です。対象サービスの提供内容・運営者・問い合わせ・データ保存方針に合わせて編集します。

## 共通の文字サイズ

一般画面・管理画面とも、`frontend/app/assets/css/main.css` の `html` をブラウザ標準の90%とし、各画面の文字サイズを `rem` 又は親要素に対する相対単位でそろえています。標準の16px設定では本文の基準が14.4pxになります。ブラウザ側の文字サイズ設定や拡大操作は妨げません。

ボタンの押下範囲や入力欄の高さは縮小せず、表・コードは狭い画面で横スクロールできます。幅760px以下の入力欄・選択欄・テキストエリアは、iOSの入力時自動拡大を避けるため16px以上を確保します。見出しの大きさを変える場合は固定の `rem` とメディアクエリを使い、PC・スマートフォンの両方で確認してください。

## 問題数・選択肢・分野を変える

- `exam.set_count`：利用できる教材番号の枠数。現在2枠で、問題の自動作成・公開は行いません。
- `exam.questions_per_exam`：従来形式 `legacy_practice` の必要問数。検証用の従来形式の5問設定を維持します。
- `exam.formats.group_practice`：公開する大問は1件、予定小問数は7又は8問。
- `exam.formats.rekiken_mock`：公開する大問は4件、各7又は8問、合計30問。
- `exam.choice_labels`：選択式の表示順とラベル。例：`["A", "B", "C"]`。選択式の選択肢はこの順序・件数にそろえ、短答にダミーの選択肢は作りません。
- `categories.major`：大分類の`value`と`label`。
- `categories.minor`：小分類の`value`・`label`・`major_category_value`。最後の値は登録済み大分類の`value`を指します。

分類の`value`は問題データから参照する識別子です。表示名だけを変える場合は`label`を変更します。各問題の`major_category_code`と`category_code`は、上記設定と一致させてください。

教材ごとの構成はDBの `format_code` で選びます。30問の模試を追加するために `questions_per_exam` を30へ変えないでください。既存5問の教材は大問未所属のまま使えます。表示順を変えても問題IDとURL用の通し番号は維持し、大問番号・大問内小問番号で並べます。

## 管理画面から教材・大問・小問を作る

管理者ログイン後、`/admin/exams` の「教材・大問」を開きます。小問一覧の入口は `/admin/questions` です。

1. 教材番号を選び、教材名・構成・下書き又は非公開の状態を保存する。
2. 大問形式では、予定小問数7問又は8問の大問を追加する。模試は4大問の合計が30問になるよう設定する。
3. 共通本文A・B等を入力する。必要な文章を分けて参照箇所・空欄のラベルを付け、先に大問を保存する。参照IDは自動生成され、同じラベルでも別本文の参照先と混同しない。
4. 「小問を作成」から問題を追加する。所属大問・大問内番号・主分類を指定し、必要な関連章節と本文全体／参照箇所を選ぶ。
5. 選択式又は語句記述を選び、本文・正答・解説・出典を入力する。下書きでは作成途中の内容を保存できる。
6. 大問全体と小問のプレビューを確認し、PC・スマートフォンの実際の表示も確認する。保存後に再読込し、本文・参照・順序・採点条件が戻ることを確認する。
7. 「公開条件を検査」で不足を確認し、「検査して教材を公開」を実行する。親教材・大問・小問の公開条件がそろったものだけが一般の演習カタログに出る。

単独大問を公開するために、残り3大問の完成は不要です。公開中の大問形式教材を未完成にする編集は拒否されるため、作業途中の保存は教材全体を非公開にしてから行います。参照中の本文を削除する場合は、先に小問側の参照を解除します。小問の並べ替えは現在所属する全小問を保ち、一覧から外しただけで問題を削除しません。

管理更新は `lock_version` で競合を検知します。409になった場合は再読込し、他の変更を確認して編集し直します。小問の内容を変更するとその小問の回答履歴、共通本文を変更するとその本文を参照する小問の履歴を削除します。保存前の画面で対象小問・件数を確認できます。分類・表示順だけの変更と同じ内容の再保存では履歴を削除せず、お気に入りと問題・選択肢IDは保持します。

### 語句記述と出典

語句記述の正答欄は1行目が模範解答、2行目以降が許容する別名・異表記です。照合はNFKC正規化と前後空白の除去だけを行い、語中空白の自動除去や曖昧一致は行いません。文字種・指定字数・最大字数・入力案内を設定し、公開時には全正答表記が条件を満たすことを検査します。回答前に正答を一般APIへ返しません。

新しい出典は `source_references` で保存します。

| 種類 | 入力内容 |
| --- | --- |
| `book` | 書名、出版社、版・刊行年、章節・項目名、実際に確認した位置。URLは任意 |
| `web` | 資料名、実際に確認したHTTPS URL、確認日 |

書籍にダミーURLを作らず、印刷頁と電子書籍の位置を区別します。Web URLは認証情報を含めず、原本PDF・全文OCR・端末内パスを問題DBへ保存しません。新形式を追加した小問では従来の `source_text` を独立編集せず、構造化出典を正本とします。版や確認位置を未確認のまま補ってはいけません。

主分類と関連章節は、その小問の回答判断に使う範囲を選びます。一般の章・節検索は両方を対象にし、章・節と文化史区分はAND条件で照合します。

## 問題JSONの形式

`content/questions.json` は旧形式を保つ検証用サンプルで、次の構造です。以下は説明用の骨組みで、本文や選択肢を省略しています。完全なデータは同梱JSONを参照してください。大問・短答を含む実問題の通常編集は管理画面から行います。

```json
{
  "schema_version": 1,
  "questions": [
    {
      "exam_number": 1,
      "question_number": 1,
      "major_category_code": "chapter_06",
      "category_code": "chapter_06_section_01",
      "is_cultural_history": false,
      "is_art_history": false,
      "cultural_history_category": null,
      "publication_status": "published",
      "content_blocks": [{ "type": "text", "text": "問題文" }],
      "explanation_blocks": [{ "type": "text", "text": "正答の根拠と各選択肢の解説" }],
      "source_text": "確認した資料名 | https://example.com/replace-with-real-source",
      "choices": []
    }
  ]
}
```

`choices`には、設定したラベル順に全ての選択肢を記載します。

```json
{
  "choice_label": "①",
  "content_blocks": [{ "type": "text", "text": "選択肢の本文" }],
  "is_correct": true,
  "display_order": 1
}
```

- このv1サンプルは選択式・正答1件です。全選択肢の`display_order`を1から連続させます。
- `publication_status`は`draft`・`published`・`private`です。
- 公開する問題は本文・全選択肢・解説・出典を記載し、従来形式の必要問数をそろえます。大問形式の公開検査は選択した教材構成を使用します。
- `source_text`は`資料名 | https://...`の形式で、複数の場合は改行して記載します。説明用のダミーURLを実際の出典として流用しないでください。書籍の紹介ページをリンクする場合は、そのURLに個別用語の解説本文があると誤認されないよう明記してください。
- `content_blocks`の対応形式は[構成の概要](architecture.md#表示ブロック)を参照してください。

初期問題は、内容の正確性と利用条件を確認したものを用意します。実在する試験の過去問をそのまま複製することを前提としたテンプレートではありません。

管理APIの小問入力には `group_id`・`group_question_number`、`answer_type`、`accepted_answers`、`input_constraints`、`related_topics`、`source_references`、`passage_references` を追加できます。共通本文は `text`・`anchor`・`blank` の安全なインライン要素を持ち、本文全体への依存は `anchor_id: null` で表します。詳細は[API・DBの概要](architecture.md)と共通型 `frontend/shared/types/learning.ts` を参照してください。

現在の選択肢は`①`〜`④`です。分類は提供された山川『世界史用語集』の目次に基づく19章・64節です。章節と文化史・美術史の扱いは、ローカル専用の `docs/classification.md` を参照してください。この文書はリポジトリの配布対象外です。公開データには用語集PDFや公式過去問PDFそのものを含めません。

## 取込と再起動

開発用Composeの起動時に`npm run db:migrate`と`npm run db:seed`を実行します。`APP_ENV`（未設定時は`NODE_ENV`）が`development`で、問題と選択肢の両方が空の場合だけ初期問題を読み込みます。すでに問題がある場合はseedを再実行しても変更しません。`production`・`test`では自動seedを行いません。

これは開発用サンプル投入の既存処理です。実問題の更新元をJSONにしたり、起動・デプロイ時に実問題を同期したりする機能ではありません。

Composeは`.env`を実行環境へ渡します。通常のNode.js運用CLIは自動では読み込まないため、直接実行する場合は[環境変数の説明](architecture.md#ローカル環境と環境変数)に従ってください。

空のDBへ明示的に取り込む場合は次のコマンドを使用します。`INPUT`を省略すると`content/questions.json`が対象です。

```bash
docker compose exec \
  -e CONFIRM=IMPORT_INTO_EMPTY_DATABASE \
  frontend npm run operations -- questions:import_content
```

取込前にデータ全体を検証し、公開セットの不足を含め不正なデータがあればトランザクション全体を取り消します。問題又は選択肢が1件でもあるDBへの取込を拒否します。稼働中サービスの問題を更新する場合は管理画面を使用してください。

`questions:export` は教材・大問・共通本文・短答・出典・参照を含むv2アーカイブを書き出します。`questions:import` はv2と従来v1を読み、件数・SHA-256・所属・公開構成を検査して空の問題領域へ取り込みます。v2では小問・選択肢に加え大問・共通本文も空であることを要求し、輸送用の大問・本文IDを取込先へ対応付けます。利用者・履歴・お気に入り・決済は含めないため、DB全体のバックアップには[移行・復元手順](migration.md)を使用します。

設定を変更したらNuxtを再起動します。画面とAPIの両方が同じ設定を使用します。

```bash
docker compose restart frontend
```

配信版をビルドして運用する場合は、`config/exam.json`を含めてNuxtの本番イメージをビルド・デプロイし直します。ブラウザの再読み込みも行ってください。

### 既存DBがある場合

原則として設定ファイルの変更だけでは既存の問題・回答履歴・購入情報は変換されません。既存の章節分類SQLは、旧分類と本文・選択肢・正答・解説・出典が一致する初期5問だけを更新する構成です。編集済み問題は手動で分類を確認してください。この分類変更では問題ID・選択肢ID・回答履歴・お気に入りを保持します。特に次の変更は、バックアップを取り、別環境で確認してから実施します。

大問対応の追加SQLは `005_grouped_questions.sql` と `006_lock_published_answer_types.sql` です。006は公開時の回答形式を固定し、下書きへ戻しても形式を変更できないようにします。移行時点の公開中問題だけに固定状態を補い、既存の下書き・非公開問題の過去の公開実績は推測しません。既存問題・選択肢IDとURL用番号を維持し、既存四択は大問未所属・内容バージョン1として扱います。構造追加だけで既存履歴を一括削除しません。SQLファイルがあることと対象DBへ適用済みであることは別なので、対象環境の実際の適用・検証結果は[検証記録](verification.md)で確認してください。

- 分類識別子を変更する：既存問題の分類も対応する識別子へ変更する。
- 問題数やセット数を減らす：設定範囲外になる問題の扱いを先に決める。
- 選択肢数・ラベルを変更する：既存問題と選択肢ID・回答履歴を整合させるデータ移行を別途設計する。現在の管理画面は、設定変更前の選択肢を新しい件数やラベルへ自動変換しません。新サービス向けの変更は、初期取込より前に行います。
- 無料範囲・価格を変更する：提供済みの利用資格や購入条件への影響を確認する。

別の資格試験を作る用途では、各コピーの`.env`に固有の`COMPOSE_PROJECT_NAME`を指定し、新しいリポジトリ・Composeプロジェクト・空のDBから始めると、既存サービスのデータを持ち込まずに設定できます。既存DBを消して差し替える手順は、このテンプレートの通常の更新手順には含みません。

既存のRails版テンプレートから更新する場合のDB移行は、[移行手順](migration.md)を参照してください。問題JSONの取込はスキーマ移行とは別の操作であり、既存DBへ問題を再投入する必要はありません。

## 課金を有効にする

現在の`payments.enabled`は`false`です。`payments.amount`の500円は未使用のテンプレート初期値で、販売価格の決定を意味しません。高校生本人・保護者の利用を含め、決済手段と価格は別途選定します。

1. `payments.enabled`を`true`にし、`free_exam_count`・`amount`を設定する。無料範囲は先頭のセットからの件数、金額は日本円の整数です。現在の対応通貨は`jpy`のみです。
2. 独立したStripe設定で、設定金額・通貨と一致する一回払いのPriceを作る。
3. `.env.example`を参照し、秘密鍵・Price ID・Webhook署名シークレット・フロントURL・販売者情報を対象環境へ設定する。
4. 対象APIの`/api/v1/webhooks/stripe`へ、購入・返金等の対象イベントが届くようにする。
5. その環境で購入・Webhookによる会員資格の反映・返金による失効を確認し、販売条件と表示を確認してから販売フラグを有効にする。

`payments.enabled=false`はサービス全体を無料で提供する設定です。`true`で販売フラグが無効の場合は、無料範囲と既存会員の利用資格を維持し、新規の購入を停止します。

購入後の戻り画面だけでは会員資格を付与しません。署名検証したWebhookを処理し、金額・通貨・Price ID等を確認した上で利用資格を反映します。定期購読・外貨ごとの価格設計等を追加する場合は、対応する決済処理と表示も実装してください。

## 派生サービスへの修正の反映

このテンプレートから作ったリポジトリへ、テンプレート側の変更は自動で反映されません。共通の修正は、対象サービスとの差分・設定・テスト結果を確認して取り込みます。複数資格を一つのDBで運営する方式や、全サービスで共通ログインを使う方式は、この初期構成には含みません。
